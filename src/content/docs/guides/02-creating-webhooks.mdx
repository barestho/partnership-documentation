## Webhook Management

Webhooks are managed via the following endpoint, using your partner credentials:

```
https://public.api.barestho.com/api/v1/partnership/webhooks/
```

Refer to the API reference for the full list of available operations (create, retrieve, delete).

A webhook is identified by its `uuid`: `/api/v1/partnership/webhooks/:uuid/`.

A webhook `url` must be unique among your webhooks. Otherwise, the creation returns `400` with the code `DUPLICATE_WEBHOOK_URL`.

A webhook `url` must:

- use `https`;
- hold no credentials (no `user:password@`);
- have a domain that resolves to **public** IP addresses only. Private, loopback and link-local addresses are refused.

Otherwise, the creation or the update returns `400 VALIDATION_ERROR`, with the detail code `INVALID_WEBHOOK_URL`. The domain is checked again before each request: if it now resolves to a refused address, the request is not sent and counts as a failed attempt.

## Developing Your Webhook

Barestho cannot reach `localhost` nor your local network. To receive events on your computer, expose your local server through an HTTPS tunnel, for example [ngrok](https://ngrok.com/):

```sh
ngrok http 3000
```

Register the public `https://` URL given by the tunnel as the webhook `url`. Then send a test event:

```
POST /api/v1/partnership/webhooks/:uuid/test/
```

The answer holds the status code returned by your server only, e.g. `{"response": {"status_code": 200}}`. A test is never retried.

<Aside type='caution'>
**Breaking change:** webhooks used to be identified by a numeric `id`. The `id` is no longer exposed: use `uuid` in the URLs. The event body sends `webhook_uuid` instead of `webhook_id`.
</Aside>

## Security

<Aside type='caution'>
Signature verification is optional but strongly recommended.  
Not implementing it exposes your system to fraudulent requests.
</Aside>

Each request sent to your webhook is signed by Barestho using an  
[**HMAC-SHA256**](https://en.wikipedia.org/wiki/HMAC) computed from your `auth_token`,  
the request payload, and the current time as a *timestamp*.  
The `auth_token` is generated by Barestho and returned once, in the webhook creation response. Read it again with `GET /api/v1/partnership/webhooks/:uuid/auth-token/`, or replace it with `POST /api/v1/partnership/webhooks/:uuid/auth-token/?action=generate`.

The following headers are included with each request:

| Header | Content |
|---|---|
| `X-Webhook-Signature` | HMAC-SHA256 signature |
| `X-Webhook-Timestamp` | Request timestamp (Unix) |
| `X-Webhook-Request-Id` | Request identifier, the same on every retry of an event. Absent on tests |

### Signature Verification

To validate that a request originates from Barestho, reconstruct the signature as follows:

1. Retrieve the timestamp from `X-Webhook-Timestamp`
2. Serialize the request body to JSON without spaces, with keys sorted alphabetically
3. Build the message to sign: `{timestamp}.{serialized_json}`
4. Compute an HMAC-SHA256 of this message using your `auth_token` as the key
5. Prefix the result with `sha256=` and compare it to `X-Webhook-Signature`

import hmac
import hashlib
import json
import time

SIGNATURE_PREFIX = "sha256="
TIMESTAMP_TOLERANCE_SECONDS = 300

def sign_payload(secret: str, payload: dict, timestamp: int):
    """
    Sign a webhook payload using HMAC-SHA256.

    :param secret: The shared secret key
    :param payload: The payload as a dict
    :param timestamp: The Unix timestamp of the request
    :return: The hex signature prefixed with 'sha256='
    """

    dumped_payload = json.dumps(
        payload, 
        separators=(',', ':'), 
        sort_keys=True,
    )

    message = f"{timestamp}.{dumped_payload}"
    signature = hmac.new(
        secret.encode(),
        message.encode(),
        hashlib.sha256
    ).hexdigest()

    return f"{SIGNATURE_PREFIX}{signature}"

def verify_signature(secret: str, payload: dict, signature_header, timestamp_header):
    """
    Verify a webhook signature and reject stale requests.

    :param secret: The shared secret key
    :param payload: The raw payload as a dict
    :param signature_header: The value of X-Webhook-Signature
    :param timestamp_header: The value of X-Webhook-Timestamp
    :raises ValueError: If the timestamp is stale or the signature is invalid
    """
    request_time = int(timestamp_header)
    if abs(time.time() - request_time) > TIMESTAMP_TOLERANCE_SECONDS:
        raise ValueError("Request timestamp is too old")

    expected = sign_payload(secret, payload, timestamp_header)

    if not hmac.compare_digest(expected, signature_header):
        raise ValueError("Invalid signature")

## Delivery and Retries

Your server must answer with a `2xx` status within **10 seconds**. Any other answer is a failure: another status, a timeout, a connection error, or a redirection (redirections are not followed).

A failed request is sent again automatically, up to **8 attempts** in total. Each retry waits after the previous attempt:

| Attempt | Delay |
|---|---|
| 1 | Right away |
| 2 | 1 minute |
| 3 | 5 minutes |
| 4 | 30 minutes |
| 5 | 2 hours |
| 6 | 6 hours |
| 7 | 12 hours |
| 8 | 24 hours |

- Delivery is **at least once**: you may receive the same event twice. Drop duplicates with `X-Webhook-Request-Id`.
- Events may arrive out of order.
- Nothing is sent to a disabled webhook, nor when your partner account is disabled. Retries pause until the webhook is enabled again.

<Aside type='tip'>
Answer `2xx` as soon as you have stored the event, then process it. A slow answer is a failure.
</Aside>

## Failed Requests

Barestho keeps the requests your server did not accept for **30 days**. A request is deleted as soon as an attempt succeeds.

```
GET /api/v1/partnership/webhooks/:uuid/requests/?status=PENDING
GET /api/v1/partnership/webhooks/:uuid/requests/:request_uuid/
```

| `status` | Meaning |
|---|---|
| `PENDING` | Automatic attempts are left. See `next_attempt_at` |
| `FAILED` | The 8 attempts failed. No automatic attempt is left |

Each request shows its `attempts` and the response of your server to the last attempt: `last_response_status_code` and `last_response`. The body is cut to 10,000 characters.

### Manual Retry

Once your server is fixed, send a request again with a read and write API key:

```
PATCH /api/v1/partnership/webhooks/:uuid/requests/:request_uuid/?action=retry
```

- `204`: your server accepted the request. It is deleted.
- `200`: your server failed again. The body is the request with this attempt recorded.
- `409 WEBHOOK_DISABLED`: the webhook or your partner account is disabled. Enable it first.

The call waits for your server, up to 10 seconds. A retry of a `PENDING` request counts as an attempt. A retry of a `FAILED` request does not change `attempts`.
