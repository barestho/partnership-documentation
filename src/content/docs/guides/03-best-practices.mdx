## Sécurité des identifiants

### Clef API

Votre token d'API est transmis en clair à chaque requête via l'en-tête `Authorization`. Il doit être traité avec le même niveau de soin qu'un mot de passe.

**Recommandations :**
- Ne jamais le versionner dans un dépôt de code (Git ou autre)
- Le stocker dans une variable d'environnement ou un gestionnaire de secrets (Vault, AWS Secrets Manager, etc.)
- Ne jamais l'exposer côté client (navigateur, application mobile)

<Aside type="note">
Barestho ne stocke pas vos tokens en clair : ils sont hashés de notre côté. En cas de perte, il n'est pas possible de le retrouver. Vous pouvez en demander un nouveau auprès de l'équipe Barestho à tout moment, sans interruption de service.
</Aside>

<Aside type="tip">
Il est possible de disposer de **plusieurs tokens d'accès** simultanément, ce qui permet par exemple de faire une rotation sans coupure.
</Aside>

---

### Token de webhook

L'`auth_token` qui est défini à la création d'un webhook est utilisé pour vérifier l'authenticité des requêtes reçues.

**Recommandations :**
- Le stocker de manière sécurisée, au même titre que votre clef API

<Aside type="note">
Barestho chiffre les tokens de webhook au repos.
</Aside>
